Simulate Verilog in your browser

Normally a Verilog simulation means installing Icarus Verilog, writing a testbench, wiring up $dumpfile and $dumpvars, and loading the result into GTKWave. RTL Bench does all of that for you — click one button and the waveform appears.

Running a simulation

Open the workbench, paste any module, and click Waves in the bottom status bar. Then press ▶ Run Testbench. That's the entire workflow.

If your module is the counter from the VHDL guide or any design with a clock and a reset, RTL Bench auto-detects the ports and drives them. You do not need to write a testbench just to see a waveform.

What RTL Bench does for you

  • Auto-generates a testbench. Every input gets driven — clocks toggle, resets pulse, and data inputs receive randomized stimulus.
  • Runs Icarus Verilog. The same open-source simulator that ships with every Linux distribution.
  • Streams back a VCD. The waveform drawer renders the value change dump directly in the browser. No GTKWave, no download, no command line.
💡 If your design has no clock, RTL Bench drives every input with random values every 10 ns. Combinational designs simulate fine without a clock.

Reading the waveform

The waveform canvas shows every top-level signal as a horizontal lane. Time runs left to right, values step vertically. Click anywhere to place a cursor.

When you want your own testbench

RTL Bench detects a self-contained testbench by looking for $dumpvars in your source. If it finds one, that testbench is compiled and run as-is — the auto-generated stimulus is skipped.

Name your testbench tb, tb_*, or *_tb so it is excluded from the top-module candidates. 

module tb;
    logic        clk = 0;
    logic        rst_n = 0;
    logic [7:0]  q;

    counter dut (.clk(clk), .rst_n(rst_n), .q(q));

    // 100 MHz clock
    always #5 clk = ~clk;

    initial begin
        $dumpfile("waves.vcd");
        $dumpvars(0, tb);

        #20  rst_n = 1;   // release reset
        #500 $finish;
    end
endmodule

Two lines matter:

  • $dumpfile("waves.vcd") names the file the viewer reads. Any name works — RTL Bench picks the newest .vcd in the working directory.
  • $dumpvars(0, tb) records every signal under tb and below. Passing 0 means "recurse into every scope".
⚠️ If you write your own testbench and forget $finish, the simulation runs until the 30-second timeout. That's the most common reason a self-written testbench hangs — always include a $finish after your stimulus.

What you don't get

Honest limitations, so you know when to reach for something else:

  • No assertions yet. SystemVerilog assert is ignored by Icarus. Use $display and check the log if you need pass/fail.
  • No coverage. The waveform is your only observation. If you need functional coverage, run a local simulator.
  • 30-second wall clock. Long-running simulations get cut off. The limit is generous for small- and medium-size designs; a large SoC test will hit it.
  • VHDL is simulated through Yosys. GHDL compiles VHDL to a netlist, then Icarus simulates that netlist. Most VHDL simulates correctly, but VHDL-specific simulation features — file I/O, assert, custom resolution functions — may behave differently than in GHDL directly.

Resizing the drawer

  • Drag the horizontal bar at the top of the drawer to resize it.
  • Click the 🗖 icon to maximise — the drawer fills the editor area.
  • The editor reserves space automatically, so the last lines of your source stay visible above the drawer.
