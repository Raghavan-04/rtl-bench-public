Privacy Policy & Data Governance Framework

Last updated: January 2025
RTL Bench operates as an open-source, web-based electronic design automation (EDA) platform. This comprehensive Privacy Policy outlines our stance on user anonymity, the strict lifecycle parameters of technical payloads submitted to our compilation backends, third-party subprocessor relationships, and explicit compliance frameworks including GDPR and CCPA/CPRA guidelines. Because RTL Bench requires no user registration, authentication tokens, or personal identifiers, your browsing and design execution workflows remain structurally decoupled from any persistent identity.

1. Information Architecture & Telemetry Scope

We practice data minimization by design. Successful structural compilations remain entirely ephemeral and unrecorded. We only capture telemetry and technical artifacts when compilation encounters a failure or structural error state.

When a compilation error occurs, the offending payload artifact is registered within a managed logging repository exclusively to diagnose syntax anomalies, isolate parser edge-cases, and safeguard platform utility. Successful compilations generate zero persistent logging records. Managed according to operational diagnostic necessity and maintenance cycles.

Maintains workspace continuity (active zoom scale, pan coordinates, syntax editor buffers, cached file arrays) during deep multi-page navigation contexts. Instantly wiped upon termination or closure of the browser tab/window.

2. Categories of Information We Do Explicitly Exclude

To provide absolute clarity on our boundaries, RTL Bench architecture ensures zero ingestion of the following data types:

  • Personal Identifiers: We do not request, process, or retain real names, personal email addresses, phone numbers, billing coordinates, or password hashes. No user account database exists.
  • Financial Data: As an open-core, freely accessible platform, we handle zero payment card transactions or banking information.
  • Precise Geolocation: We track no device-level GPS or localized Wi-Fi positioning parameters.
  • Behavioral Advertising Profiles: We build no cross-context behavioral advertising profiles, nor do we ingest data for programmatic ad networks.

3. Lifecycle Management of Uploaded Hardware Descriptions

When you push code into our compilation pipeline via text paste or directory tree upload, the transmission travels exclusively over TLS 1.3 encrypted channels. Once received by our FastAPI backend framework:

  • Sandboxing: The raw files are written into a temporary, restricted Unix directory sandbox assigned zero outbound network socket permissions and bound to a strict 30-second execution watchdog timer.
  • Ephemeral Processing: Yosys, GHDL, and Icarus Verilog execute within this isolated context to generate simulation VCD outputs and structural netlists. Upon request completion, the temporary directory is scrubbed from disk.
  • Conditional Diagnostic Logging: If a compilation request successfully passes, the source files leave no persistent trace outside your active browser session. If compilation faults or triggers an error, execution diagnostics and payload snapshots are mirrored to Google Cloud Firestore strictly for debugging and error-handling analysis.
  • Client Caching: The calculated JSON netlist representation is returned to your browser client and stored exclusively within volatile browser memory (`sessionStorage`), leaving no permanent server footprint.

4. Third-Party Infrastructure & Subprocessor Disclosures

RTL Bench relies on industry-standard, high-reliability cloud subprocessors to maintain availability, high-speed asset distribution, and deep logic analytics:

  • Google Cloud Platform (Firestore): Provides managed, enterprise-grade NoSQL database structures for logging diagnostic error artifacts when compilation faults occur. Governed by Google Cloud's Data Processing Addendum (DPA).
  • Google Analytics 4 (GA4): Collects anonymized traffic statistics. Google utilizes cookies to evaluate engagement patterns. Review Google's Privacy Policy and how Google handles site telemetry data.
  • Google Fonts: Typography assets (Inter and JetBrains Mono) are dynamically requested from Google Content Delivery Networks, transmitting basic client IP connection metadata necessary for asset delivery.
  • jsDelivr CDN: Supplies external script bundles (such as the Eclipse Layout Kernel — ELK.js) directly to the client browser environment for local graph coordinate calculations.
  • Render Infrastructure: Hosts our containerized FastAPI backend and static frontend distribution network. Render captures basic operational HTTP ingress metrics in alignment with Render's Corporate Privacy Policy.

6. Statutory Rights & Regulatory Compliance

A. European Union & UK Users (GDPR Compliance)

For individuals accessing RTL Bench from within the European Economic Area (EEA) or United Kingdom, processing of technical request metadata is executed under the lawful basis of legitimate interests (ensuring software stability, preventing service abuse, and providing real-time hardware design compilation). Because we maintain no user profiles or account repositories:

  • The right of access and data portability can typically be managed instantly by inspecting your local browser session storage.
  • Requests to scrub specific diagnostic log iterations from our transient error logs can be submitted directly through our repository issue tracker.
  • You retain the absolute right to lodge a complaint with your local supervisory data protection authority.

B. California Residents (CCPA / CPRA Compliance)

Under the California Consumer Privacy Act (CCPA) and California Privacy Rights Act (CPRA), users are entitled to know what categories of personal data are gathered. Because RTL Bench collects zero consumer personal data, sells no user information to third-party data brokers, and engages in no cross-context behavioral tracking for monetary consideration, we naturally maintain full operational compliance. We do not honor "Do Not Track" (DNT) browser header flags differently than standard operations because our baseline analytics already run without persistent cross-site behavioral tracking profiles.

7. Technical Data Security Controls

We implement stringent defense-in-depth measures to protect runtime infrastructure:

  • In-Transit Encryption: Absolute enforcement of HTTPS protocols utilizing strong cipher suites and modern TLS configurations across all domain entry points.
  • Execution Isolation: Automated compilation scripts run inside heavily isolated process containers with zero filesystem persistence beyond the instant build window.
  • Database Access Restrictions: Google Cloud Firestore endpoints are locked down behind strict Identity and Access Management (IAM) controls, rejecting all unauthenticated or client-side direct socket queries.

8. Children's Online Privacy Protection (COPPA)

RTL Bench is structured as an engineering utility tool intended for academic, professional, and experimental hardware design. We do not target, market to, or knowingly solicit data interaction from minors under the age of 13. If you believe a minor has improperly transmitted code artifacts containing identifying metadata, please reach out via our repository channels for immediate removal.

We reserve the right to amend this Privacy Policy dynamically as platform features, subprocessors, or regulatory landscapes evolve. Substantive modifications will be indicated by adjusting the "Last updated" timestamp stamped at the head of this document. Continued engagement with RTL Bench subsequent to any modification confirms your ongoing acknowledgment of the revised governance terms.
